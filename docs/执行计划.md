# 能力平台化改造执行计划

## 1. 文档目标

- 目标：在现有三进程架构基础上，逐步接入 `skill` 生态、`mcp` 生态、`plugin` 生态，并补齐统一能力模型、审批、观测、记忆治理、规划与多模态能力接入。
- 原则：不破坏当前固定三进程模型，不让 Wails 承担编排职责，不让 Go 持有多轮会话真相。
- 范围：`Agent-brains` 负责编排与策略，`Eion-tools` 负责能力注册与执行，`Wails-v3` 负责发现、观测、审批与管理台。

## 2. 工作方式

### 2.1 并行 Agent 分工

- `AGENT-A 架构编排组`
  - 负责 `Agent-brains`
  - 负责能力编排、选择、策略、审批等待点、上下文裁剪
- `AGENT-B 运行时生态组`
  - 负责 `Eion-tools`
  - 负责 capability registry、skill runtime、mcp client、plugin host、provider 配置
- `AGENT-C UI 与协议组`
  - 负责 `Wails-v3`
  - 负责能力管理台、审批 UI、执行轨迹、协议解码与展示
- `AGENT-D 验收组`
  - 不承担主开发
  - 负责验收文档、证据收集、回归测试、跨模块联调验收

### 2.2 执行约束

- 所有任务必须绑定唯一任务编号
- 所有任务必须能映射到一条或多条验收项
- 所有高风险改动必须包含回归验证
- 所有生态接入必须通过统一 capability manifest 暴露

  - 影响范围
  - 回归点
  - 对应验收编号

## 9. 风险控制

- 不允许把多轮会话真相迁移到 Go 或前端
- 不允许让 Wails 接管 Agent 生命周期
- 不允许新生态接入绕开统一 capability registry
- 高风险能力必须走审批链路
- 视频生成等高成本能力必须走异步任务，而不是塞进普通同步 tool call

## 10. 与验收文档对应关系

- 本文任务编号全部以 `EXEC-*` 开头
- 验收文档中的对应项以 `ACPT-*` 编号
- 一般映射规则：
  - `EXEC-P0-001` 对应 `ACPT-P0-001`
  - `EXEC-P1-003` 对应 `ACPT-P1-003`
  - `EXEC-P2-005` 对应 `ACPT-P2-005`
