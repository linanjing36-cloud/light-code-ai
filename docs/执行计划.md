# Hermes Agent v2.0 执行计划

**版本**: v2.0  
**日期**: 2026-06-30  
**基准**: 基于当前代码现状（P0/P1底座已验收、P2-001/002/003后端已完成）

---

## 1. 计划概述

### 1.1 当前基线

P2-001(planner)、P2-002(memory tiering)、P2-003(provider store)的**Erlang后端核心已实现并编译测试通过**（commit `5a31d8f`）。当前执行计划聚焦于补全剩余工作：Proto协议扩展、Go侧桥接、前端UI、LLM记忆工具、体验打磨、多模态起步。

### 1.2 执行原则

1. **契约先行**：先扩panel.proto，三侧同步更新codec（Erlang panel_pb_codec / Go panel_codec / TypeScript类型）
2. **后端先于前端**：每个功能先完成Erlang RPC handler和Go侧透传，再做UI
3. **增量可验证**：每个任务独立可测试，不依赖大规模合并
4. **不破坏既有链路**：所有Proto变更向后兼容（新字段optional、新方法追加）
5. **三进程边界不变**：所有编排逻辑仍在Erlang，Go/Wails不持有Agent真相

### 1.3 并行分工

| 角色 | 负责模块 | 对应目录 |
|------|---------|---------|
| Agent-A（编排组） | Agent-brains Erlang侧 | `Agent-brains/src/` |
| Agent-B（运行时组） | Eion-tools Go侧 | `Eion-tools/`、`Wails-v3/internal/` |
| Agent-C（UI组） | Wails前端 | `Wails-v3/frontend/`、`Wails-v3/internal/brain/` |
| Agent-D（验收组） | 测试/文档/回归 | `test/`、`cmd/panel_*_e2e/`、`docs/` |

#### TASK-M1-001：Panel Proto扩展（Provider/Memory/Cancel）

- **优先级**: P0
- **负责人**: Agent-A + Agent-B
- **模块**: `Agent-brains/proto/panel.proto`、`Wails-v3/proto/panel.proto`
- **动作**:
  1. 在panel.proto中新增Provider相关message：
     - `ProviderConfig { id, name, api_base, api_key_masked, models, enabled, is_default, created_at, updated_at }`
     - `ModelRoute { model, provider_id }`
     - `RiskPolicy { risk_level, action }`
     - `ListProvidersResult { providers }`
     - `UpsertProviderArgs { id, name, api_base, api_key, models, enabled }` / `UpsertProviderResult { ok }`
     - `DeleteProviderArgs { id }` / `DeleteProviderResult { ok }`
     - `SetDefaultProviderArgs { id }` / `SetDefaultProviderResult { ok }`
     - `SetModelRouteArgs { model, provider_id }` / `SetModelRouteResult { ok }`
     - `TestProviderArgs { id }` / `TestProviderResult { ok, error, latency_ms }`
     - `GetRiskPoliciesResult { policies }`
     - `SetRiskPolicyArgs { risk_level, action }` / `SetRiskPolicyResult { ok }`
  2. 新增Memory相关message：
     - `MemoryEntry { session_id, tier, key, content, source, created_at, updated_at }`
     - `ListMemoriesArgs { session_id, tier, query? }` / `ListMemoriesResult { memories }`
     - `AddMemoryArgs { session_id, tier, content }` / `AddMemoryResult { key }`
     - `DeleteMemoryArgs { session_id, tier, key }` / `DeleteMemoryResult { ok }`
     - `ClearMemoriesArgs { session_id, tier }` / `ClearMemoriesResult { count }`
     - `SetSessionProviderArgs { session_id, provider_id }` / `SetSessionProviderResult { ok }`
  3. 新增执行控制message：
     - `CancelExecutionArgs { session_id }` / `CancelExecutionResult { ok }`
  4. 新增Plan stream event：
     - `PlanGenerated { plan_json, goal, step_count }`
     - `PlanStepUpdate { step_index, status }`
  5. 更新method注释，加入新方法名
  6. 同步更新`Wails-v3/proto/panel.proto`（保持同源）
  7. 重新生成Go代码：`protoc --go_out=. panel.proto`
  8. 重新生成Erlang代码：`rebar3 compile`（gpb自动生成）
- **交付物**: 更新后的panel.proto（两份）、生成的Go pb代码、生成的Erlang pb代码
- **回归点**: 旧方法(start_session/send/list_capabilities等)的编解码不回归

#### TASK-M1-002：Erlang panel_server RPC Handler扩展

- **优先级**: P0
- **负责人**: Agent-A

     - `delete_provider` → `provider_store:delete/1`
     - `set_default_provider` → `provider_store:set_default/1`

     - `set_risk_policy` → `provider_store:set_policy/2`
     - `list_memories` → `memory_tier:get_by_session/2`

     - `set_session_provider` → `provider_store:set_session_provider/2`

#### TASK-M1-003：Erlang agent_fsm取消执行支持

- **优先级**: P0
- **负责人**: Agent-A
- **模块**: `Agent-brains/src/agent/agent_fsm.erl`
- **动作**:
  1. `agent_fsm`新增`cancel` cast处理：
     - `thinking`状态：取消pending LLM调用（通过bridge_manager:cancel_req/1），生成canceled observation，回到idle
     - `acting`状态：取消pending tool调用，生成canceled observation，回到idle
     - `idle`状态：无操作，返回{error, not_running}
  2. `bridge_manager`新增`cancel_req/1`：标记Ref为canceled，收到响应时忽略
  3. 终态final answer中标记canceled状态
- **交付物**: agent_fsm cancel处理、bridge_manager cancel支持
- **回归点**: 正常send→thinking→acting→idle流程不回归

## 4. 风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| Proto扩展破坏旧链路 | P0 | 低 | 新字段optional，e2e覆盖旧方法 |
| Plan stream事件与chunk时序错乱 | P1 | 中 | plan_generated在第一个chunk前发送；终态final前确保plan_step_update收敛 |
| 记忆工具被LLM滥用（反复写入） | P2 | 中 | memory_tier层做幂等(key为hash)，设置单轮写入上限(如5次) |
| API Key明文存储安全顾虑 | P2 | 低 | 掩码输出+文档说明v2.1升级到OS密钥环 |
| Erlang-native tool打破tool执行抽象 | P1 | 中 | 在agent_fsm acting中统一dispatch：Erlang-native tool直接处理，其余走bridge_manager |
| 前端单文件main.ts过大(>1500行) | P2 | 高 | M2阶段拆分为模块(services/stores/views)，当前M1阶段允许增量追加 |
